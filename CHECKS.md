- Добавлены сценарии DEB/RPM и DMG/PKG, отдельные артефакты Installers/Portable,
  проверки установки, запуска и удаления перед upload. Нативные сборки и CI

- Локально прошли **233 unit-теста**, включая проверку платформы/архитектуры,
  отказ при провале bridge/трея, точную лицензию, отсутствие личных данных,

  `build/checks-v0.5.0-browser.log` (локальные, не входят в дистрибутив).
- Checks ограничен push в ветки, PR и ручным запуском: релизные теги исключены.
  Обновлённый workflow проходит actionlint; реальное событие тега здесь не отправлялось.

  это проверка зависимостей и Xvfb, без сертификации desktop/Wayland/видимого трея.
  Mint 22.x использует базу Ubuntu, отдельная Mint-сессия не проверялась.
- macOS CI должен проверить strict codesign, DMG в режиме read-only, установленный
  PKG, реальный Cocoa/JS bridge и удаление только созданного `.app` с сохранением
  синтетических данных в пользовательских каталогах. Developer ID/нотариализации нет.
- Windows Setup проверялся ранее на v0.4.1 (ниже); новый v0.5.0 должен пройти свой CI.
  Windows hosted CI не подтверждает запись WGC/WASAPI на интерактивной Windows 11.
- Влияние системного регулятора громкости на конкретном аудиодрайвере не измерялось.
  Музыка других процессов исключается выбранным process-loopback режимом; отключать
  источник внутри вкладки встречи нельзя, если нужен её звук.

## Исправление меню тестового EXE — 27 октября 2026

Проверка сгенерированного `module.tray_windows.c` показала: Nuitka 2.8.10 дважды
вызывает `Items.Add(...)` для выражения `Items.Add(...).Click += handler`.
Получаются четыре пункта вместо двух, с неработающими копиями. В CPython
отдельное воспроизведение создаёт только два пункта.
Создание пунктов вынесено в переменные перед подключением обработчиков.
Прежняя самопроверка вызывала контроллер напрямую и не выявляла этот дефект.
Теперь проверяются реальные пункты меню, их действия и развёрнутое состояние окна.
После первой пересборки строгая проверка дополнительно воспроизвела окно вне
экрана: WinForms оставлял координаты `(-32000, -32000)` после Show. Восстановление
теперь сохраняет нормальную геометрию, нормализует состояние после Show и возвращает
окно в рабочую область доступного монитора. Видимость сверяется через Win32.
Прошли **216 unit-тестов**, **4/4 source portable checks**, **7/7 tray checks**.
Исправленный Windows 11 EXE в `dist/tray-menu-fix2/` также прошёл **17/17 full
checks**, **4/4 portable checks**, **7/7 tray checks**. Вызваны реальные пункты
меню; проверены Win32-видимость, развёрнутое состояние и пересечение с монитором.
Тестовый архив v0.4.1 создан без Hashsum; прежняя запущенная копия сохранена.

## GitHub Actions и другие платформы

По предоставленным журналам первого запуска Windows собрался, Linux упал
при инициализации QtCore/поиске xcb, macOS arm64/x64 — на подписи данных
в Contents/MacOS. Внесены исправления: PySide6 6.9.3, явные пути Qt и перенос
ресурсов macOS перед подписью. Эти ошибки в следующем предоставленном запуске
не повторились. Успешный Windows-тест не подтверждает Linux/macOS.

В следующем предоставленном запуске Linux и обе macOS прошли упаковку и
запуск Chromium, но остановились на `native_ui_js_bridge`. Linux-журнал
подтвердил блокировку CSP для eval и inline-стиля pywebview. Добавлено разрешение
`unsafe-eval` для генератора JS API; inline-скрипты/стили остаются запрещены.
Smoke-окно использует `text_select=True`, как основное окно приложения.
После этого локально проходят **197 unit-тестов**, **4 UI-регрессии** и
**4/4 source portable checks на Windows**. CSP-регрессия сначала воспроизвела
ошибку со старой политикой, затем прошла с исправлением. Проверено, что
inline-скрипты и inline-стили по-прежнему блокируются. Нативный повторный запуск
Linux/macOS с исправленным CSP ещё требуется; сборки локально не выполнялись.

Локально после исправления проходят **197 unittest-тестов** и actionlint.
Новые регрессии проверяют Qt-конфигурацию, перенос данных с сохранением
бинарников/ссылок, повторный вызов, отказ от перезаписи и выход за границы bundle.

Новые диагностики macOS arm64/x64 подтвердили наличие всех UI-файлов,
успешные календарь/Chromium и `before_load=false`, `bridge_injected=false`,
`loaded=false`. Загрузка страницы не достигла внедрения JS-моста.
Добавлено ATS-исключение для HTTP на `127.0.0.1` перед подписью `.app`;
на macOS smoke-окно теперь видимо. Диагностика отдельно проверяет реальный
HTTP-ответ страницы и сохраняет ранние стадии загрузки окна.
Локально проходят **200 unit-тестов**, включая plist/HTTP/redirect-регрессии,
и **4/4 source portable checks на Windows** с HTTP `200 text/html`.
В следующих архивах macOS arm64/x64 исключение ATS уже присутствует,
но HTTP-проба из Python заканчивается `timed out`; окно не достигает `before_load`.
Следовательно, прежняя попытка исправления через ATS проблему не решила.

Текущее исправление: macOS загружает настоящий интерфейс через native HTML-режим
pywebview без HTTP-сервера. Все поставляемые CSS/JS включены в документ с новым
CSP nonce; посторонние inline-скрипты и стили по-прежнему запрещены. Обычный запуск
и smoke-check используют общий загрузчик. Неиспользуемое ATS-исключение удалено.

После изменения проходят **203 unit-теста**, **5 браузерных регрессий** (включая
собранный HTML и блокировку постороннего inline-кода) и **4/4 source portable checks
на Windows в каждом из двух режимов: HTTP и прямой HTML**. Это проверка Windows,
а не доказательство работы Cocoa. CI теперь проверяет окно macOS из исходников
до компиляции и повторно в готовом приложении; при сбое сохраняет стеки потоков.
**Нативный macOS-запуск нового загрузчика ещё требуется. Локальные сборки и CI
не запускались.**
