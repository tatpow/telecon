# Проверка Телекона — 16 октября 2026

Телекон — vibecode / [GVP (Generated Viable Product)](https://github.com/tatpow/GVP).
Ниже указаны выполненные проверки и их границы.

## Текущее состояние

OBS заменён на FFmpeg. Кадры точного HWND окна выделенного Chromium поступают
через Windows Graphics Capture; звук только дерева процессов этого браузера —
через ProcTap/WASAPI. Выбор рабочего стола, общего системного звука или микрофона
в качестве скрытого запасного источника отсутствует.

Настройка «Не давать компьютеру засыпать» сохраняется в SQLite. Временные
Windows power requests удерживаются при активном расписании и при ручной записи,
освобождаются после паузы без активной записи и при закрытии. Параметры питания
и блокировки Windows не меняются.

## Выполнено

- Полный набор `python -m unittest discover -s tests -v`: **91 тест, OK**.
- Набор прошёл в отдельном сборочном окружении CPython
  3.12.10. Проверка `app.py --self-check` в нём подтвердила запуск Chromium,
  видео и звук через FFmpeg, native-окно pywebview и JavaScript → Python API.
- После сообщения об ошибке камеры добавлены регрессии: закрытие известного
  диалога «Понятно», повтор клика после перерисовки, независимое выключение камеры
  при неготовом микрофоне, повтор подключения при перекрытой кнопке. Переход
  `private-join` переводится в `mic=off&camera=off` только для указанной лекции;
  остальные параметры и чужие запросы сохраняются. Главная Телемоста допустима
  для входа в аккаунт, но не как ссылка лекции.
- В живом Телемосте проверен предпросмотр `mic=off&camera=off`: показаны кнопки
  «Включить микрофон» и «Включить камеру». В Chromium дополнительно воспроизведён
  блокирующий HTML-диалог ошибки: самопроверка закрыла его и выключила оба
  устройства. Для этого не использовались корпоративный аккаунт или реальные
  устройства; это отдельная проверка логики обработки интерфейса.
- `compileall`, `node --check ui/app.js`, `git diff --check`, `pip check`: без ошибок.
- На настоящем Windows x64 проверено создание и освобождение power request.
- Пройдена реальная короткая запись синтетического Chromium через Windows
  Graphics Capture → FFmpeg, параллельно WASAPI → FFmpeg. Файл MKV читается,
  обе дорожки декодируются. Проверен кадр с изображением страницы, звук тестового
  тона подтверждён измерением RMS. Обычный GDI-захват оказался чёрным и заменён
  на Windows Graphics Capture до завершения работы.
- Проверена изоляция при двух отдельных Chromium-процессах с разными картинками
  и тонами 440/880 Гц: сохранена картинка выбранного окна; отношение целевого
  тона к постороннему составило около 8948. Личные окна, микрофон и аккаунты
  в этих тестах не использовались. Все записи и профили теста — во временных
  каталогах вне исходников.
- В дополнительном тесте целевой тон отключён, второй браузер продолжал
  звучать. Запись продолжилась более пяти секунд после отключения тона;
  RMS последней секунды равен 0.0. Тишина не прервала захват.
- В браузерном стенде с теми же UI-файлами и Python API проверены сохранение
  выключенного флажка сна и его повторное включение. «Проверить FFmpeg» возвращает
  версию, режим захвата и доступную папку. Ошибок JavaScript в консоли нет.
  База стенда временная; настоящие лекции и авторизация в нём отключены.
- Ранее по предоставленной ссылке Телемоста проверены iframe и селекторы
  входа/медиа. Корпоративный вход, отмена, последовательный запуск и cleanup
  также покрыты регрессионными тестами.

## Границы проверки

- Запись реальной лекции под корпоративным аккаунтом вуза пока не подтверждена.
  Нужно один раз войти через «Запись и аккаунт → Войти в Яндекс», затем проверить
  короткую запись встречи и её воспроизведение.
- Успех проверки FFmpeg означает готовность компонентов, а не подтверждённый
  вход на встречу. Обе читаемые дорожки могут содержать тишину/статичные слайды,
  если именно это происходило во встрече.
- Окно нельзя сворачивать; блокировка Windows прерывает запись. Power requests
  не отменяют ручной сон, закрытие крышки и корпоративные политики.
- Новая запись поддерживается только на Windows x64 с process-loopback API
  (build 20348+). Проверка Nuitka-дистрибутива выполняется перед упаковкой ZIP:
  результат находится в `SELF-CHECK.json` конкретного релиза, версии компонентов
  и хеши исходников — в `BUILD-INFO.json`. Чистая Windows и установщик не проверялись.
- Инструкции сборки для Windows, Linux и macOS — в [BUILDING.md](BUILDING.md).
  На этой машине проверяется только Windows x64. Linux/macOS-рецепты относятся
  к экспериментальному интерфейсу; запись и предотвращение сна там не поддержаны.

Версии проверенных окружений: Python 3.13 и 3.12.10, pywebview 6.2.1, FFmpeg 7.1,
imageio-ffmpeg 0.6.0, windows-capture 2.0.1, proc-tap 1.1.1.
