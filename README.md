# Телекон — календарь лекций и запись

Отдельное desktop-приложение для Windows: pywebview, SQLite, автоматическое
подключение к Яндекс Телемосту через Playwright и локальная запись через FFmpeg.
OBS не требуется. Приложение не зависит от Telegram-бота.

Это **vibecode** и **GVP — Generated Viable Product**: основная реализация создана
ИИ под руководством человека, который задаёт требования и проверяет результат.
Термин используется в смысле [концепции GVP](https://github.com/tatpow/GVP).

Тёмный интерфейс сочетает карточки Memos и миникалендарь. Все лекции идут по
времени начала, самые ранние сверху. Есть поиск, фильтры, создание и редактирование.

## Установка и запуск

Нужны 64-битные Windows 11 (либо Windows build 20348+), Python 3.10+ и Edge
WebView2 Runtime. Для звука отдельного процесса используется Windows API,
[требующий build 20348+](https://learn.microsoft.com/en-us/samples/microsoft/windows-classic-samples/applicationloopbackaudio-sample/).

Из каталога проекта в PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m playwright install chromium
.\.venv\Scripts\python.exe app.py
```

При обновлении уже созданного окружения повторите установку `requirements.txt`
и перезапустите Телекон. FFmpeg входит в пакет `imageio-ffmpeg`. Дополнительные
Python-компоненты `windows-capture` и `proc-tap` устанавливаются тем же способом;
виртуальный аудиокабель и отдельная настройка звуковых устройств не нужны.
Проверенная конфигурация: Windows x64, Python 3.13. На других версиях Python
должны быть доступны совместимые wheels этих native-компонентов. На macOS/Linux
новый backend записи не поддерживается.

## Настройки

Откройте **Настройки** внизу левой панели (при небольшом окне прокрутите
панель вниз). Выберите папку записей вне исходного проекта. Пустое поле означает
`Видео / Telecon` в домашней папке пользователя. В разделе «Дополнительные настройки записи»
можно выбрать собственный `ffmpeg.exe`; по умолчанию используется комплектный.
Нажмите **Проверить запись**: проверяются запуск кодировщика, форматы, компоненты
захвата и возможность записи в папку. Эта проверка сама не записывает экран и
не подтверждает корпоративную авторизацию.

**Не давать компьютеру засыпать** включено по умолчанию. Пока активно расписание
или идёт запись, приложение удерживает временные запросы Windows для системы
и дисплея. При паузе расписания запрос снимается, если запись уже закончилась;
при закрытии приложения он освобождается после завершения записи. Флажок можно
отключить в любой момент. Схема электропитания не меняется.
[Windows power requests](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-powersetrequest)
предотвращают сон по бездействию, но не отменяют ручной сон, закрытие крышки,
корпоративные политики и блокировку Windows. Заблокированный рабочий стол
прерывает запись. Сворачивание встречи даёт чёрное видео с продолжающимся звуком.

## Корпоративный аккаунт вуза

Выберите **Войти в Яндекс**. Приложение откроет [главную Телемоста](https://telemost.yandex.ru/)
в отдельном
видимом Chromium. Нажмите «Войти» и пройдите авторизацию корпоративного аккаунта,
включая SSO и подтверждение, если они требуются. Затем закройте это окно Chromium.
Пароль и код вводятся только на странице Яндекса/вуза. Сессия остаётся в локальном
профиле и используется для следующих лекций. Настройка аккаунта и запись
одновременно не выполняются.

Если Телемост явно показывает «Войдите в аккаунт», автоматический гостевой вход
отменяется с просьбой авторизоваться. При истечении сессии войдите снова.
Приложение не обходит ограничения вуза и допуск организатора.

## Использование

Над календарём находятся две основные кнопки: **Добавить лекцию (N)** и
**Быстрое подключение (F)**. Эти клавиши работают и в русской раскладке, но
не срабатывают при вводе текста. Кнопка в левом верхнем углу сворачивает
и разворачивает боковую панель; её состояние запоминается в окне приложения.
Технические подписи о компонентах записи убраны с главного экрана.

Добавьте название, ссылку `telemost.yandex.ru/j/...`, локальное
время начала и окончания. Префикс `https://` можно не писать: приложение добавит
его перед сохранением и открытием ссылки. По умолчанию вход начинается за две минуты до занятия;
интервал можно изменить от 0 до 120 минут. Пример ссылки на конкретный созвон
(используется в карточке лекции, а не для настройки аккаунта):
[встреча Телемоста](https://telemost.yandex.ru/j/42574758760781).

В «Настройках» задайте длительность пары по умолчанию (1–1440 минут,
изначально 90). При создании лекции время окончания рассчитывается от начала;
если вы изменили окончание вручную, оно сохраняется. Уже добавленные лекции
новая настройка не меняет.

«Быстрое подключение» над списком лекций открывает форму со ссылкой и датой/временем
окончания. Окончание заранее рассчитано по длительности пары, его можно изменить.
Кнопка «Подключиться и записать» запускает встречу сразу, в том числе при
выключенном расписании. Такая встреча появляется в общем списке; ход подключения
и ошибки видны там же.

Включите расписание и оставьте приложение запущенным; окно можно свернуть. Перед встречей Телекон
проверит FFmpeg, откроет ссылку в своём профиле Chromium, выключит микрофон и
камеру и подключится. После подтверждения входа и повторной проверки устройств
начинается запись. Реальные камера и микрофон остаются доступны: их можно
включить кнопками встречи. Кнопка на карточке позволяет подключиться сразу.
Одновременно выполняется одна лекция; истёкшие занятия отмечаются пропущенными.

При загрузке экрана встречи Телекон задаёт наблюдаемые параметры Телемоста
`mic=off&camera=off` только для выбранного созвона. Разрешения камеры и микрофона
при этом сохраняются. Если возникает известное окно «Включить видео не удалось»,
приложение нажимает «Понятно», повторяет выключение устройств и проверяет
устойчивое состояние. Перехваченный диалогом клик «Подключиться» повторяется
после проверки устройств, до трёх попыток. Если состояние подтвердить нельзя,
вход не объявляется успешным. Эта обработка не исправляет неисправную, занятую
другим приложением или запрещённую политиками Windows камеру.

Видео получает [Windows Graphics Capture](https://github.com/NiiightmareXD/windows-capture/tree/main/windows-capture-python)
по точному HWND окна выделенного браузера. Звук получает
[ProcTap](https://github.com/m96-chan/ProcTap) только из дерева процессов этого
Chromium. Кадры и звук кодируются FFmpeg в MKV: H.264, 1920×1080, 15 кадров/с,
AAC, 48 кГц, стерео. Пропорции окна сохраняются. Другие приложения и системный
микрофон не являются источниками записи. В выделенном браузере не открывайте
другие вкладки со звуком: они принадлежат тому же дереву процессов.

Телекон и окно Телемоста можно сворачивать: расписание и запись продолжаются
в фоновых потоках Python. Пока свёрнут Телемост, в видео идут чёрные кадры,
а звук его процесса продолжает записываться. После разворачивания изображение
возобновляется. Запись можно начать и при уже свёрнутом окне встречи. Закрытие
окна Телемоста и блокировка Windows по-прежнему прерывают запись. Наличие аудиодорожки не доказывает,
что преподаватель говорил: тишина на встрече остаётся тишиной в файле.

Если окно Телемоста свёрнуто во время записи, Телекон один раз за это
сворачивание подаёт звуковой сигнал, показывает уведомление Windows и значок
предупреждения поверх своей иконки на панели задач. В приложении появляется
сообщение с кнопкой «Открыть окно Телемоста». После восстановления окна значок
и текущее уведомление убираются. Простое сворачивание Телекона не требует
предупреждения: картинка встречи от этого не теряется.

В «Настройки → Предупреждение о свёрнутом Телемосте» каждый из трёх
способов включается отдельно. Громкость сигнала — от 0 до 100%, начальное значение
50%; 0 отключает звук. Сигнал — мягкая мелодия из трёх нот с плавным затуханием.
«Прослушать» проверяет выбранную громкость до сохранения.
Настройки сохраняются и применяются к текущей записи. Громкость Windows и встречи
не меняется, звук предупреждения из процесса Телекона не включается в аудиодорожку
выделенного Chromium. Уведомление Windows отправляется без собственного системного
звука, поэтому переключатель звука и громкость остаются независимыми от него.
Системный режим «Не беспокоить» может скрыть всплывающее уведомление; окно
приложения всё равно показывает предупреждение. Ошибка канала предупреждений
отображается в интерфейсе и не останавливает запись.

Запись заканчивается по времени окончания лекции. Пауза расписания останавливает
только будущие запуски; отдельная кнопка остановки завершает текущую запись.
При закрытии Телекона приложение сначала сохраняет свой файл и закрывает браузер.
При ошибке частичный файл сохраняется для восстановления, а лекция получает
ошибку. Успех подтверждается кодом выхода FFmpeg и чтением обеих дорожек.

Время — локальное время компьютера. Синхронизации с Google Calendar нет.
Расписание не исполняется при закрытом приложении или спящем компьютере.

## Удаление карточки и видео

Кнопка корзины на карточке открывает выбор:

- **Только запись в календаре** — карточка удаляется, видео остаётся в папке.
- **Запись в календаре и видеофайл** — после подтверждения удаляются оба.
  Удаление файла с диска нельзя отменить.

Приложение удаляет только привязанный к этой карточке обычный видеофайл,
проверяя его идентификатор и путь. Подменённый файл, ссылка или каталог
не удаляются. Если файл занят или нет доступа, карточка сохраняется и
показывается ошибка. Уже отсутствующий файл не мешает удалить карточку.
Во время записи удаление недоступно. Старые видео, для которых прежняя версия
не сохраняла путь в базе, автоматически не сопоставляются с карточками:
их можно удалить вручную из папки записей.

## Качество, FPS и разрешение

В настройках доступны четыре уровня качества: максимальное, сбалансированное,
компактное и экономное. Более сильное сжатие уменьшает файл; качество звука
остаётся прежним. FPS выбирается из списка или вводится вручную: целое число
от **1 до 60**. Меньше кадров помогает снизить нагрузку при записи слайдов;
больше кадров делает движение плавнее, но требует больше ресурсов.

Разрешение выбирается из доступных размеров, по экрану или задаётся вручную.
Ширина и высота — чётные числа от 64 пикселей, в пределах физического
разрешения монитора. В настройках показаны экран и параметры будущей записи.
Авто по умолчанию ограничено Full HD и размером экрана; на 4K-мониторе можно
выбрать 4K отдельно. Если окно встречи запускается на меньшем мониторе,
видео автоматически уменьшается с сохранением пропорций. Неполный кадр
дополняется чёрным; свёрнутое окно использует те же размеры и FPS.

По умолчанию: сбалансированное качество, 15 FPS, авто до 1920×1080.
Для компактных слайдов подходят 720p, 5–10 FPS и компактное качество.
Настройки применяются к следующей записи в MKV или MP4; текущая запись
продолжает работать с параметрами, выбранными при её запуске.
Фактическая плавность зависит от обновления окна встречи и производительности ПК.

## Формат, минимальная длительность и имя файла

В настройках доступен выбор **MKV** или **MP4**. По умолчанию остаётся MKV:
он подходит для длительной записи и восстановления после прерывания.
MP4 удобен для просмотра на большинстве устройств. Оба формата содержат
H.264-видео и AAC-звук с одинаковым качеством. Для MP4 после записи выполняется
перенос дорожек без перекодирования, с подготовкой быстрого начала воспроизведения.
При ошибке этого шага исходный MKV сохраняется, а на карточке появляется ошибка.

**Минимальная длительность видео** задаётся в настройках в целых минутах,
от 0 до 1440. `0` отключает ограничение. Если фактическая длительность меньше
порога, видео не попадает в итоговые сохранённые файлы: временный файл удаляется,
а на карточке появляется причина. Это относится и к ручной остановке записи.
Равная порогу длительность сохраняется. Ошибочные или нечитаемые частичные
файлы сохраняются для восстановления с сообщением об ошибке.

**Имя видеофайла** задаётся шаблоном. По умолчанию:
`{name}-{date}-{duration}`. В настройках сразу виден пример результата.

| Атрибут | Значение | Пример |
| --- | --- | --- |
| `{name}` | Название лекции, пробелы заменяются на `_` | `История_архитектуры` |
| `{date}` | Дата начала записи, ДДММГГ | `181026` |
| `{date_iso}` | Дата начала записи, ГГГГ-ММ-ДД | `2026-10-18` |
| `{time}` | Фактическое начало записи, ЧЧ-ММ | `11-56` |
| `{time_end}` | Фактическое окончание записи, ЧЧ-ММ | `13-21` |
| `{duration}` | Фактические полные минуты, округление вниз | `85` |

Например: `История_архитектуры-181026-85.mkv`. Расширение добавляется автоматически,
по выбранному формату, в том числе если шаблон уже заканчивается на `.mkv` или `.mp4`. При совпадении имени
добавляется `-2`, `-3` и далее; существующие файлы не перезаписываются.

Секунды, плановая длительность и ID не являются доступными атрибутами.
Если название содержит запрещённые символы, пустое или непригодно для Windows,
вместо `{name}` используется ID встречи. Если ошибочен весь шаблон, итоговое
имя — `<ID встречи>` с расширением выбранного формата. Уточняющий диалог не требуется.
Дублирующий атрибут `{длительность}` удалён; в ранее сохранённых шаблонах
он автоматически заменяется на `{duration}` при обновлении.

Шаблон и минимальная длительность применяются к новым запускам; уже созданные
видео не переименовываются и не удаляются при изменении настроек. Пока идёт
запись, данные пишутся в уникальный `.partial.mkv` вне исходников. Итоговое имя
появляется после проверки файла и порога длительности. Для MP4 затем выполняются
перенос дорожек и проверка итогового файла; короткое видео в MP4 не переносится.

## Данные и ограничения

База `lectures.sqlite3`, настройки и профиль Chromium находятся в
`%LOCALAPPDATA%\LectureAssistant`. Существующие лекции сохраняются при обновлении;
старые параметры OBS больше не используются. В базе также сохраняются сведения
о связанных видеофайлах, их длительности и причинах несохранения. Второй экземпляр блокируется до
восстановления прерванных лекций. Видео хранится в выбранной папке вне исходников.
Cookies, пароли и записи не добавляйте в репозиторий.

16 октября 2026 на тестовой ссылке проверены iframe `/private-join/` и селекторы
`turn-on-mic-button`, `turn-on-camera-button`, `enter-conference-button`,
`end-call-alt-button`. Внешняя боковая панель показывает управление звонком ещё
до входа, поэтому не считается его подтверждением. Изменения Телемоста,
повторная авторизация и ожидание допуска могут потребовать действий пользователя.
Запись с реальным корпоративным аккаунтом вуза требует отдельной проверки.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Тесты используют временные базы и заглушки. Дополнительно на Windows выполнена
настоящая запись синтетического Chromium с изображением и тестовым
звуком через Windows Graphics Capture, WASAPI и FFmpeg, включая сворачивание,
чёрные кадры со звуком и возврат картинки. Проверен запуск фонового обработчика
в свёрнутом native-окне Телекона, фильтрация коротких файлов, шаблоны имён
и оба способа удаления. Подробности — в `CHECKS.md`.

Последняя собранная версия — `v0.3.2b` от 18 октября 2026: качество, FPS и
разрешение записи. Готовый EXE прошёл **15 из 15** самопроверок; итог находится
в `SELF-CHECK.json` внутри релиза.
Тексты для публикации и коммита: [RELEASE_NOTES.md](RELEASE_NOTES.md)
и [COMMIT_MESSAGE.md](COMMIT_MESSAGE.md).

## Сборка Windows-билда

Используйте Windows x64 и отдельное окружение CPython 3.12. Скрипт
`build_windows.py` запускает Nuitka/MinGW, добавляет FFmpeg и Chromium, проверяет
готовый EXE и только после успешной проверки создаёт ZIP. Существующие релизы
не перезаписываются. Для воспроизводимой сборки закреплены версии зависимостей:

```powershell
py -3.12 -m venv build\builder-venv
.\build\builder-venv\Scripts\python.exe -m pip install -r requirements-build.lock.txt
.\build\builder-venv\Scripts\python.exe -m playwright install chromium
.\build\builder-venv\Scripts\python.exe -m unittest discover -s tests -v
.\build\builder-venv\Scripts\python.exe build_windows.py --version v0.3.2b --no-hashsum
```

Nuitka использует свой совместимый MinGW (при необходимости скачивает его).
Установка Visual Studio для этого варианта не требуется. При изменении исходников
выбирайте новый номер версии. `requirements-build.txt` остаётся незакреплённым
вариантом для обновления инструментов; готовый билд записывает фактические версии
в `BUILD-INFO.json`. Метка `v0.3.2b` сохраняется в названии релиза и свойствах EXE;
числовая версия Windows для неё — `0.3.2.0`. Старые четырёхкомпонентные версии
также поддерживаются. Флаг `--no-hashsum` исключает контрольные суммы из отчёта
и не создаёт файл `.zip.sha256`; без этого флага хеши создаются как раньше.

Скрипт явно включает Windows-модуль pywebview: стандартный плагин Nuitka 2.8
исключает `webview.platforms.win32`, добавленный в pywebview 6.2.1
([описание разработчика pywebview](https://github.com/r0x0r/pywebview/issues/1817)).
В папку также включаются app-local библиотеки Microsoft Visual C++ x64 Runtime;
для сборки они должны быть установлены в Windows.

Результат: папка `dist/Telecon-Windows-x64-<версия>/` с `Telecon.exe` и архив
с таким же названием. Нужно распаковывать и переносить всю папку. Python и OBS
на целевой машине не нужны; Microsoft Edge WebView2 Runtime должен быть установлен.
FFmpeg и Chromium уже включены в папку. Для `v0.3.2b` используется `--no-hashsum`: отдельного
файла контрольной суммы нет.

Команда ниже запускает проверку именно готового EXE. Она использует временные
данные и синтетические видео/звук, а не корпоративный аккаунт или настоящую лекцию:

```powershell
.\dist\Telecon-Windows-x64-v0.3.2b\Telecon.exe --self-check "$env:TEMP\telecon-self-check.json"
```

Отчёт `SELF-CHECK.json` в папке релиза подтверждает запуск комплектного Chromium,
FFmpeg и native-модулей, изображение/звук, сворачивание и восстановление окна встречи, работу
свёрнутого Телекона, показ и снятие системного предупреждения/значка,
освобождение запроса питания и связь
настоящего pywebview-окна с Python. Проверка на этой Windows не заменяет проверку
на чистой машине и вход в корпоративный аккаунт вуза. Установщик не создаётся.

## Сборка на других платформах

Полные команды Windows, Linux и macOS приведены в [BUILDING.md](BUILDING.md).
Windows x64 — поддерживаемая платформа записи. На Linux/macOS можно экспериментально
собрать интерфейс, календарь и вход в аккаунт; захват окна/звука и предотвращение
сна для этих ОС пока не реализованы. Такие сборки нужно проверять на самой целевой
ОС; Windows-билд не является сборкой для Linux/macOS. Закреплённый Windows lock-файл
зависимостей не предназначен для установки на других платформах.
